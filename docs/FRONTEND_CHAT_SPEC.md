# Техническое задание: Веб-интерфейс чата разбора задач (MAX Mini App)

## 1. Концепция и цель
Разработка интерактивного веб-приложения (Mini App), встроенного в мессенджер **MAX**, для проведения разборов задач по физике (7–9 классы) между учениками и преподавателями (тьюторами).

Сервис решает проблему изолированного общения в МАКС:
* Исключает необходимость ручного поиска пользователей по никнеймам.
* Объединяет в едином окне **текстовый чат**, **обмен фото решений/чертежей**, **видеосвязь в Яндекс Телемосте** и **геймификацию (XP / звания)**.

---

## 2. Архитектура решения

### 2.1. Стек технологий
* **Frontend**: Vanilla JS / React (без внешних тяжелых зависимостей), адаптированный под размеры мобильных экранов МАКС (от 375px) и десктоп.
* **Backend**: FastAPI (Python), асинхронная архитектура, WebSocket для мгновенной доставки сообщений.
* **База данных**: SQLite / PostgreSQL (SQLAlchemy + aiosqlite).
* **Интеграция с МАКС**: MAX Mini App Bridge (`window.WebApp`), push-уведомления через MAX Bot API (`platform-api2.max.ru`).
* **Видеосвязь**: Яндекс Телемост (прямой запуск встречи из шапки веб-интерфейса).

## 4. Экранная модель веб-интерфейса

### 4.1. Шапка (Header)
* Аватар и имя собеседника (Ученик / Преподаватель).
* Номер и тема задачи (например: *«Задача #4: Статика и КПД»*).
* Кнопка **`[📹 Телемост]`** — запуск/вход в видеоконференцию без выхода из чата.
* Индикатор статуса: 🟢 В работе / 🟡 Ожидание / 🔵 Звонок активен.

### 4.2. Область сообщений (Chat Feed)
* Баллуны сообщений с разделением по автору (свои справа, собеседника слева).
* Отображение времени отправки и статуса прочтения.
* Поддержка изображений (чертежи задач, рукописные решения, графики).
* Поддержка формул (LaTeX / KaTeX) для физических законов ($F = mg$, $\eta = \frac{A_п}{A_з}$).

### 4.3. Панель ввода (Input Bar)
* Поле ввода текста с поддержкой многострочности.
* Кнопка прикрепления фото / скана ДЗ.
* Кнопка быстрой отправки.

### 4.4. Завершение разбора (Footer Action)
* Кнопка **`[✅ Вопрос решен]`**:
  * Доступна ученику после объяснения материала.
  * По клику открывает окно подтверждения и оценки разбора (1–5 звезд).
  * Автоматически начисляет +100 XP преподавателю и +50 XP ученику.
  * Меняет статус задачи на `COMPLETED`.

## 5. Модель данных и API (Backend)

### 5.1. Таблица `task_messages`
```sql
CREATE TABLE task_messages (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    task_id INTEGER NOT NULL REFERENCES tasks(id),
    sender_id INTEGER NOT NULL REFERENCES users(id),
    text TEXT NOT NULL,
    photo_url TEXT,
    is_read BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### 5.2. API Эндпоинты
* `GET /api/tasks/{task_id}/messages` — получить историю сообщений задачи.
* `POST /api/tasks/{task_id}/messages` — отправить сообщение (с текстом и/или фото).
* `POST /api/tasks/{task_id}/complete` — завершить задачу («Вопрос решен») с начислением опыта.
* `WebSocket /ws/tasks/{task_id}` — real-time подключение для мгновенного обмена сообщениями.

### 5.3. Синхронизация с ботом (Push Notifications)
Если один из участников закрыл веб-приложение, бэкенд отправляет push-сообщение в МАКС через `POST /messages`:
> 📨 *Преподаватель Алексей отправил сообщение по задаче #4:*  
> *«Посмотри на второе плечо рычага...»*  
> `[💬 Открыть чат разбора]`

## 6. Этапы реализации
* **Этап 1 (Текущий - в боте):** Полная эмуляция взаимодействия кнопками (`[📹 Телемост]`, `[💬 Написать через бота]`, `[✅ Вопрос решен]`).
* **Этап 2:** Создание базы сообщений `task_messages` и REST/WebSocket эндпоинтов в FastAPI.
* **Этап 3:** Верстка адаптивного SPA-клиента (HTML/CSS/JS) в стиле Telegram/MAX WebApp.
* **Этап 4:** Подключение `window.WebApp` и открытие по кнопке из бота.
